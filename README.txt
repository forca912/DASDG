DASDG 1.1.0 — SoftwareX revision software release

This source distribution unifies training, inference,
epoch-boundary resume, evidence validation, and preserved reproduction workflows.
No performance result is generated by installation or software acceptance.
The accepted 1.1.0rc1 runtime is preserved in 1.1.0. Version and distribution
metadata changes are recorded in release_provenance.json. Public publication and
new DOI assignment are separate actions; no new DOI is asserted by this package.

INSTALLATION
Python 3.10–3.12; NumPy >=1.26,<3; PyTorch >=2.3,<3.
Generic API compatibility is tested on the recorded acceptance environments only.
For the frozen paper experiments use Python 3.12 / PyTorch 2.3 CUDA 12.1.
With an existing compatible torch/numpy runtime:
  python -m pip install --no-index --no-deps dist/dasdg-1.1.0-py3-none-any.whl
This installs the release wheel, not CUDA or all dependencies from zero.
Use an isolated environment when an older dasdg / dasdg-reuse / evidence package
is already installed. Normal dependency-resolving installation is also supported:
  python -m pip install dist/dasdg-1.1.0-py3-none-any.whl

API AND EXAMPLE
  from dasdg.api import Config, fit, predict
  result = fit('dataset.npz', 'new_run', Config(), device='cuda')
  prediction = predict('new_run/best.pt', values, observed, device='cuda')
The dataset must contain complete finite float32-convertible flow[T,N], boolean
observed[T,N] (True=observed), and chronological integer split[3] boundaries.
Labels must be complete even where historical inputs are masked. Missing target
labels are unsupported. Predict accepts historical values and masks only;
unobserved history may be NaN. Output is [horizon,node] in original units.
Supply the available history prefix to retain carry-forward state.
  python examples/minimal_reuse.py --output /absolute/path/new_example --device cpu
  dasdg train --dataset dataset.npz --config config.json --output new_run --device cuda
  dasdg train --dataset dataset.npz --config config.json --output new_run --device cuda --resume
  dasdg predict --checkpoint new_run/best.pt --history history.npz --output prediction.npy --device cuda
Resume restores optimizer, scheduler, RNG, best weights and epoch history.
It rejects changed data/config/code/environment and concurrent output use.
Only epoch-boundary recovery is supported; interruption during an epoch may lose
that epoch. Normalization uses complete training labels reduced in float64.
This custom-data API is not the frozen PEMS float32 preprocessing protocol.
Available API models: dasdg, gwn_duration, gru_duration.

FROZEN PAPER REPRODUCTION
frozen/persistent contains unchanged R1 sources and configs for PEMS03/04/08.
frozen/dgcrn_md contains unchanged formal-v3 adapter and runner sources.
source_provenance.json records byte-identical files. Data, masks, trained weights
and external author model source are not included in this source bundle.
Keep the original processed data/masks and the pinned paper environment.
Legacy v1.0.2 modules remain accessible, e.g.:
  python -m dasdg.run_dasdg_reproduction --help
R1 persistent workflow:
  python frozen/persistent/run.py --help
  python frozen/persistent/run_suite.py --help
DGCRN formal workflow needs pinned upstream files obtained separately:
The external DGCRN source imports pandas; install pandas in that separate
benchmark environment as well (pip install 'dasdg[external-dgcrn]'). It is not
a dependency of the generic API. A wheel contains the APIs; use the source
distribution for frozen workflows and their configurations.
  python tools/acquire_frozen_sources.py --output frozen/dgcrn_md/upstream
  python frozen/dgcrn_md/tests_contract.py
  python frozen/dgcrn_md/formal_preflight.py --data-root /absolute/path/data --output /absolute/path/new_formal --device cuda
  python frozen/dgcrn_md/run_formal_matrix.py --package frozen/dgcrn_md --data-root /absolute/path/data --output /absolute/path/new_formal --device cuda
The last command launches the 6-job formal budget; do not run it for this short
software acceptance or repeat already completed experiments.
The original formal compatibility builder also verifies GCN-M files; this is a
preserved dependency of that workflow, not evidence of a formal GCN-M comparison.
DGCRN formal resume skips completed jobs; partial-job optimizer resume is unsupported.

DGCRN EXTERNAL COMPATIBILITY
DGCRN is an adapted external baseline, not a native model of the generic API.
Pinned upstream: tsinghua-fib-lab/Traffic-Benchmark,
commit b9f8e40b4df9b58f5ad88432dc070cbbbcdc0228.
The upstream LICENSE says MIT, but the README badge says CC BY-NC-SA. The conflict
has not been clarified by the rightsholder. This bundle does not redistribute
DGCRN author source; local acquisition/preparation does not resolve upstream terms.
Preserve upstream attribution and documents; seek clarification before redistribution.
For a standalone user-supplied checkout at that commit:
  dasdg dgcrn-prepare --upstream /absolute/path/Traffic-Benchmark --output /absolute/path/new_compat
It verifies net.py/layer.py/LICENSE/README hashes, makes an isolated compatibility
copy, preserves notices, and records the same two edits used in formal-v3.
For exact paper reruns use frozen/dgcrn_md, not a newly invented training protocol.

EVIDENCE TOOLS
  dasdg status
  dasdg evidence audit-dgcrn results.tar.gz --report new_audit.json
  dasdg evidence registry
The evidence submodule's registry is its archival v0.3.0 scope record; the unified
software scope is returned by dasdg status. It is not a new performance claim.
The preserved package_manifest.json and evidence check-engine describe their
original full experiment archives, including files omitted from this source-only
distribution. Do not use them to validate this reduced bundle. Use SHA256SUMS.txt
and source_provenance.json for this distribution's included files.

ACCEPTANCE
run_server_release_acceptance.sh runs isolated wheel install + CPU tests + actual
CUDA short-training/resume/prediction tests on synthetic fixtures. It refuses a
silent CPU fallback for GPU checks. Both success and failure preserve evidence.
No PEMS long training, raw data modification, public push or shutdown occurs.
GPU checkpoint equivalence is assessed within the recorded environment, not across
arbitrary hardware/software versions. See acceptance JSON for actual verification.
Third-party downloaded compatibility outputs and trained artifacts must not be
silently incorporated into this MIT core distribution.
